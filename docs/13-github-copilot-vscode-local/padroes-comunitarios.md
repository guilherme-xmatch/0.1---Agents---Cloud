# 60 padrões comunitários observados

Este arquivo registra 60 padrões, estratégias ou maneiras de organizar GitHub Copilot localmente no VS Code observadas em repositórios públicos.

Leitura de rigor:

- `Verificado`: o repositório e o caminho do artefato foram observados diretamente na busca pública.
- `Inferência`: o propósito foi deduzido a partir do nome do arquivo ou da convenção do diretório quando o conteúdo completo não foi auditado linha a linha.
- `Julgamento`: `Maduro / recomendo`, `Emergente / recomendo com ressalvas` ou `Frágil / não recomendo`.

## 7. Síntese da amostra comunitária

Convergências maduras:

1. versionar artefatos do Copilot em `.github/` como parte do próprio repo
2. separar baseline global, instruções contextuais e tarefas reutilizáveis
3. decompor papéis em planner, reviewer, tester, architect e implementer
4. usar hooks para guardrails determinísticos, especialmente formatação, build mínimo e bloqueio de segredo
5. distribuir MCP por `mcp.json`, `sample` ou `template` conforme o nível de confiança

Pontos frágeis recorrentes:

1. persistência de formatos legados `chatmode`
2. naming inconsistente e artefatos sem semântica clara
3. arquivos `backup`, `.old` e variantes de casing como `MCP.json`
4. sobreposição documental entre `AGENTS.md`, instructions, prompts e agents

Leitura final:

- a comunidade mais madura converge para um pacote local versionado no repo
